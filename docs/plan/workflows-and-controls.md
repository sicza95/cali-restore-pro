Delivery target: a complete application workflow before image editing. Route names and control grouping below are proposals; behaviors and privacy limits follow the confirmed baseline. Reuse [the existing UI direction](../ui-direction.md), shared components and Storybook rather than creating a second visual system.

Opaque route IDs must not include user/project names. Client project search decrypts only authorized local/listing records; the server cannot offer plaintext full-text project search. Authorization/deep-link errors must not disclose another account's content.

**First use:** register/sign in → verify as needed → create/unlock vault and retain recovery material → choose session-only or explicitly remembered trust → project library → new restoration project with default object/surface → attach original file bytes → real encrypted local save. No image-engine gate is required to organize files and settings. A local-only account sees intentional cloud eligibility information, not an endless failed-upload queue.

**Cloud use:** an eligible owner explicitly enables hosting and accepts quota responsibility → publishes encrypted content → sees local-versus-remote acknowledgement. An invited account accesses only its accepted project. Existing local projects never upload implicitly after a feature grant.

**Collaboration:** owner selects verified recipient and assessment/financial/history scopes → generic email → recipient acceptance → authorized-client encrypted activation → authorized view/edit. Removing a member shows pending until acknowledged, then blocks access/future epochs. New-device unlock is separate from sign-in. See [access lifecycle](access-and-encryption.md).

**Return/offline/recovery:** reopen acknowledged encrypted local work → show pin completeness, pending queue and remote revision separately → reconnect with policy and base checks → merge clearly independent changes on the client or preserve conflicting alternatives. Restore backup independently of the source server. Account switch, manual lock, sign-out and forget cannot silently discard the only usable local copy.

**Daily assessment:** select surface/photo → prepare reference or accept aligned detail → calibrate → edit master/damage/work phase → preserve checkpoint → compare → estimate → report. Before the engine phase, all these screens and controls exist, with a clearly labelled fixture/review path where computation is unavailable. Real administrative, storage and membership actions stay functional.

## Every control has a contract

At M-08, maintain a machine-readable control registry alongside UI code. Each entry records stable ID, label/help translation keys, command/query contract, permission/prerequisites, value source, functional-or-mock status, owner milestone and failure/empty/locked state. Browser coverage checks registry entries appear in their expected composition, with a documented reason for conditionally unavailable controls. This prevents a toolbar-only mock from hiding missing inspectors/settings/dialogs.

Mock controls may select tools, edit temporary review parameters, open sheets, navigate fixture steps and preview fixtures. An engine command without an implementation opens a labelled preview or is visibly unavailable with its reason; it never reports a durable drawing/calibration/alignment/history action. Keep fixture providers in explicit review compositions/adapters, with no production fallback to synthetic measurements. Platform saves acknowledge only actual encrypted transactions/remote commits.

## Definition of mock completeness versus product completeness

M-08 covers control presence, input validation, navigation, accessibility, permissions and faithful state presentation. It does not close drawing/measurement/import/report accuracy requirements. M-09 calculators and M-11 encoders can be tested against known numeric/geometric fixtures independently. M-16 verifies the same contracts against real committed geometry, selected authorized versions and actual source assets; stale jobs may never publish into a replaced surface/revision.

Default per-stroke commit saves completed strokes; manual mode keeps independent per-layer drafts and Commit/Discard. Before Commit, Undo removes pending strokes; after Commit, a batch is one history step. Point editing that layer resolves its pending draft explicitly; switching layers does not. The final engine must persist completed strokes/pending batches and bounded recent surface history, while allowing the one interrupted pre-lift stroke to be lost. Two fingers navigate; Pencil draws; optional finger drawing remains off by default. History gestures retain the confirmed two-/three-finger double-tap entry and shared rapid-tap window, with physical timing/arbitration validated later.
