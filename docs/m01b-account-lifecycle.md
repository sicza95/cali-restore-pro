# M-01b account lifecycle

This slice builds on merged [M-01a PR #4](https://github.com/sicza95/cali-restore-pro/pull/4) at `1f7e1b5` on `feat/storybook-foundations`. It adds public account access, credential recovery, account security and development mail. M-02 expands settings and administration.

Registration creates a pending member. Verification activates it and sign-in starts a session. Duplicate registrations preserve the existing verifier. Registration, resend and recovery acknowledge valid requests without revealing account existence or claiming delivery. Credential changes require the current password to have been verified in the last five minutes. A new email address takes effect after confirmation at that address. The previous address receives a security notice. Password reset, password change and completed email change atomically revoke all sessions and outstanding account links. Policy transitions also invalidate links. Sessions otherwise retain the manual sign-out policy from M-01a.

The [OpenAPI contract](../contracts/openapi.json) defines the eight lifecycle actions. Mutations use the existing trusted Origin and bounded JSON checks. Authenticated mutations also require the session CSRF token. Each link contains 256 random bits, has a purpose and account, and is consumed under a transaction. Verification expires after 24 hours. Password reset and email change expire after 30 minutes. Reissuing a link replaces the previous one. The browser removes the link fragment from the address bar and submits the token only when the user acts. This follows the token and referrer handling guidance in the [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).

The application commits each link and mail job together. PostgreSQL stores the link digest and the account, purpose, target email and expiry. The queued mail payload is sealed with AES-GCM using the mounted mail key. The worker locks one eligible job through bounded SMTP delivery and retries with exponential delay from two minutes up to one hour. Expired jobs or jobs that reach eight failed attempts become terminal. Sent and terminal jobs retain operational metadata for up to seven days and clear the encrypted payload. A crash after SMTP acceptance can deliver a duplicate, which carries the same single-use link. Mail and audit entries contain account metadata only. Audit entries use account IDs and fixed action names. The application role can now insert pending accounts and update credential fields to support the lifecycle, while bootstrap, guard and audit history writes retain their existing boundaries.

The UI uses the existing DM Sans and theme tokens with quiet navigation, an opaque form surface and the product mark. The security view shows the signed-in account, password and email controls, and actual server sessions. English and Hungarian are available in the interface and mail. Registration and recovery use the selected language. Security notices use the account language recorded at registration. See [deployment and mail configuration](../deploy/README.md).

## Verification

The isolated validation run passed all four product Playwright tests, including real registration, verification by mail, sign-in, password change and session revocation, password reset by mail, email change by mail, revoke-all and logout. The Go race suite, packaged bootstrap smoke, Storybook build and 11 Storybook browser tests also passed locally. The iPad landscape and portrait security screenshots were inspected.

- The Go race suite exercises disposable PostgreSQL, including single-use and purpose checks, expired links, concurrent consumption, credential and policy revocation, stale confirmation, durable retry, retry exhaustion and payload removal.
- The packaged operator smoke verifies mounted bootstrap, sign-in, confirmation rotation, logout and the final-superuser safeguard.
- The product Playwright suite uses real same-origin requests, PostgreSQL and Mailpit. The lifecycle test requires `IDENTITY_SMOKE_DISPOSABLE=1` and loopback origins. Set `SMOKE_ORIGIN` and `MAIL_SMOKE_ORIGIN` for nondefault ports. It uses synthetic addresses and leaves them in the disposable stack.
- UI checks cover light and dark themes, iPad landscape and portrait, localization, accessible controls, connection recovery and invalid links. Production relay qualification, physical Safari and restore-safe revocation remain separate gates.
