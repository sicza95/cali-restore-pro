## Import, storage and editing

- Attach original identifies the image by its container bytes. Unsupported, damaged and over-limit inputs produce distinct English and Hungarian messages and retain the selection. An isolated worker processes one image at a time per tab. Cancel, navigation and vault lock terminate the worker and abort staging or the pending project transaction. The final IndexedDB transaction commits the project revision and publishes the staged original together. If the browser exits before commit, existing staging cleanup removes abandoned records after 24 hours on the next staging operation.
- The unchanged source, filename and MIME type use the existing encrypted original format. The working manifest, proxy and each tile use a separate HKDF purpose and AES-GCM with a fresh IV per write. Authentication binds each record to account, project, original and part. Working records are device-local and rebuildable from authenticated original ranges. Reopen reads a proxy first. Zoom uses visible tiles with up to two reads in flight per view. Missing or invalid proxy data triggers a rebuild. A missing or invalid tile falls back to the proxy in that region. Removing the local original or forgetting the vault deletes its working records.
- Working pixels use upright coordinates and 8-bit sRGB PNG. Browser decoders handle native profile conversion and EXIF transforms on JPEG/PNG/WebP; the worker uses an sRGB canvas. TIFF assumes sRGB for supported unprofiled samples. HEIF uses primary-item container transforms and the supported SDR transfer, converting explicit BT.709 transfer to sRGB. For RAW, the worker uses the embedded JPEG's EXIF orientation when present and otherwise uses the container orientation. The working PNGs contain rendered pixels without copied source metadata.
- Original sharing, hosted transfer and portable backup continue to carry the existing source parts. A locally restored original can regenerate its working assets on open. Source metadata stays out of the M-11 report encoders. M-13 can use the working manifest's upright raster dimensions and explicit embedded-preview flag.

## Supported variants and limits

| Family      | Implemented variant                                                                                                               | Verification                                                                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| JPEG        | Complete 8-bit sequential or progressive JPEG ending at EOI, using browser color management                                       | Progressive JPEG with EXIF orientation 6 and sampled colors                                                             |
| PNG         | Single image, with transparency retained                                                                                          | Transparent colored fixture, 8192 × 4096 import, truncated and oversized rejection                                      |
| TIFF        | Classic TIFF, either byte order, single page, uncompressed chunky 8-bit strips. Grayscale, RGB or unassociated RGBA, assumed sRGB | Big-endian grayscale, mirrored orientation and pixel oracle                                                             |
| HEIC/HEIF   | Primary SDR 8-bit HEVC still with supported BT.709/sRGB or unspecified NCLX; untagged content assumes sRGB                        | Real HEVC encodes with SDR tags, primary pixel checks and container rotation                                            |
| DNG         | Classic TIFF-based DNG with a complete embedded JPEG in a supported IFD range                                                     | Synthetic JPEG offset and container-orientation test, plus iPhone 12 Pro 3024 × 4032 and Leica M10 5952 × 3968 previews |
| CR2         | Canon CR2 with a complete embedded JPEG in a supported IFD range                                                                  | Synthetic strip and orientation case, plus Canon EOS 600D 5184 × 3456 preview                                           |
| CR3         | Canon CR3/C-RAW with a JPEG in the Canon PRVW UUID and optional CMT1 orientation                                                  | Synthetic PRVW and CMT1 test, plus EOS M50 RAW and the published C-RAW sample, both 1620 × 1080                         |
| WebP / AVIF | Additional native still-image paths with header bounds and browser decoder availability                                           | WebP alpha fixture. AVIF uses the bounded BMFF path and remains outside the qualified matrix                            |

RAW sensor demosaic, RAW without a supported complete JPEG preview, BigTIFF, compressed/tiled/profiled TIFF, animation, multilayer images, HDR and wide-gamut/ICC HEIF are outside this slice. RAW dimensions describe the upright preview. They are unsuitable as claims about sensor fidelity or native resolution. The TIFF/RAW parser uses classic TIFF metadata, and the CR3 parser uses the documented Canon preview box layout. [ExifTool EXIF tags](https://exiftool.org/TagNames/EXIF.html) · [LibRaw CR3 parser](https://github.com/LibRaw/LibRaw/blob/master/src/metadata/cr3_parser.cpp)

- **Input** up to 256 MiB per original, encrypted in 1 MiB chunks. Up to 64 MiB for a contiguous encoded raster or embedded preview. Native raster preflight caps declared dimensions at 12,288 px per edge and 40 Mi pixels. TIFF is capped at 24 Mi pixels and HEIF at 16 Mi pixels. The worker has a 120-second active-job deadline. Box, directory and chunk walks have finite entry and byte limits.
- **Working assets** one proxy up to 1536 px per edge and a pyramid up to a 4096 px edge and 8 Mi pixels at the finest level. Smaller levels halve each edge. Each tile is at most 512 × 512, with a 2 MiB encoded limit. The proxy is capped at 12 MiB and the per-image cache at 48 MiB. Browser decoding can allocate one full bounded raster. The worker reuses a tile canvas and releases the source bitmap. This is a limit on admitted work, not a measurement of browser peak memory.
- **Dependencies** the package lock pins `libheif-js` 1.23.5, loaded on demand by the worker. The production HTTP policy permits Wasm compilation for that worker and permits local blob image URLs. Other app scripts retain the existing script policy. [Decoder source and LGPL license](https://github.com/catdad-experiments/libheif-js/tree/d8ec4bc3bc5bf8055975577bccbbc7e1d7313c2d) · [Underlying Wasm build and source](https://github.com/catdad-experiments/libheif-emscripten)
